# 独自クエリ

タブ追加ダイアログでアカウントと「クエリ」を選択し、S式のクエリを入力する。
作成後はタブ上部の検索欄を編集して「検索・保存」を押すと、条件を保存して再取得する。
無効な入力はエラーを表示し、適用済みの条件を維持する。保存したクエリは再起動後も復元される。

Issue [#1](https://github.com/cormojs/lilium/issues/1) の機能を、
[#2 の構文・AST例](https://github.com/cormojs/lilium/issues/2#issuecomment-5335736152) と
[#3 の検索欄](https://github.com/cormojs/lilium/issues/3) に沿って実装している。

```lisp
(from (merge (tl :local) (tl :public))
  :where (or (contains .txt "hogehoge")
             (not (null? .media)))
  :order (sort .id))
```

この例は選択アカウントのLocalとPublicから取得し、本文に `hogehoge` を含む投稿、
またはメディアのある投稿をID昇順に表示する。同じIDの投稿は1件にまとめる。

| 式 | 動作 |
| --- | --- |
| `(tl :home)` | Homeを取得。`:local`、`:public`、`:favourites` も利用可能 |
| `(merge source source ...)` | 2つ以上の取得元を統合。同じ取得元の指定は1回にまとめる |
| `(from source :where condition :order ordering)` | 取得元・条件・表示順を指定。`:where` と `:order` はそれぞれ省略可能 |
| `(contains .txt "文字列")` | 本文の部分一致。大文字小文字を区別する。HTMLタグや属性は検索せず、文字参照は復号する |
| `(null? .media)` | 添付メディアがない投稿に一致 |
| `(not condition)` | 条件を否定 |
| `(and condition condition ...)` | 2つ以上の条件すべてに一致 |
| `(or condition condition ...)` | 2つ以上の条件のいずれかに一致 |
| `(sort .id)` | IDの昇順。`:asc` または `:desc` を第2引数に指定可能 |

利用できるフィールドは `.txt`（本文）、`.media`（メディア）、`.id`（投稿ID）、
`.acct`（APIから取得したアカウント表記）、`.cw`（CWテキスト）。
`contains` は文字列フィールド、`null?` はメディアの空配列または空文字列を判定する。
並び順は `.id` のみ対応し、数値IDは精度を落とさず比較する。

`:where` 省略時はすべての投稿を表示する。`:order` 省略時はID降順（新しい投稿順）。
この並び順、部分一致、フィールドの意味は、Issueに未指定だった部分の初期実装での定義。

文字列はダブルクォートで囲み、`\"`、`\\`、`\n`、`\r`、`\t` を利用できる。
関数名・キーワード・フィールド名は大文字小文字を区別する。
未知の関数、フィールド、取得元、重複オプション、引数不足は取得前にエラーとする。
クエリは最大10000文字、式の入れ子は最大64段まで。

## 取得・更新

- 検索対象は選択アカウントでAPIから取得したタイムライン。サーバー全体の全文検索ではない。
- 初回と「さらに取得」では取得元ごとに1ページずつ取得する。フィルターに一致しないページでも、さらに過去を取得できる。
- 取得位置はフィルター・ソート前の取得元ごとに保持する。絞り込み後の表示順には依存しない。
- 一部の取得に失敗しても成功した取得元は表示する。「さらに取得」で失敗した取得元を再試行できる。
- Home・Local・Publicは既存のストリーミング／ポーリング機構を利用し、追加・削除に追従する。Favouritesは手動の「再取得」で更新する。
- ストリーム受信時は取得元ごとに新しい400件を保持する。切り捨てた履歴は「さらに取得」で再取得できる。
- クエリの変更・再取得・タブを閉じる操作で、古いリクエスト結果を破棄し、購読を解除する。
